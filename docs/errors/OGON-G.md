# Error class `OGON-G` — Generation conflict

> Diagnostics that fire when `ogon gen` would overwrite a file the CLI
> does not own.

This page covers: **what**, **when**, **examples**, **remedy**, **escape**,
**troubleshoot** (DOC-018).

---

## What

`OGON-G` covers the conflict detection in `ogon gen`. The CLI marks a
file as "owned by ogon" when its content contains one of these
markers:

- `Code generated` (the standard Go convention)
- `ogon:generate`
- `ogon-generated`

If a planned file already exists and does NOT contain one of these
markers, `ogon gen` refuses to overwrite it (exit 5) unless you pass
`--force`.

| Code         | Title                                | Exit | When                                                                  |
|--------------|--------------------------------------|------|------------------------------------------------------------------------|
| OGON-G0001   | Unowned file                          | 5    | A planned file exists and lacks the "Code generated" marker.           |
| OGON-G0002   | Plan invalid                          | 5    | The generator's plan produced no files.                                  |
| OGON-G0003   | Template not found                    | 5    | A custom template referenced in `ogon.yaml` does not exist.              |

---

## When

`OGON-G` fires on every `ogon gen <thing>` invocation that would write
to a file that already exists. With `--dry-run`, conflicts are
surfaced as warnings; without `--dry-run`, they are exit-5 errors.

---

## Examples

### OGON-G0001 — Unowned file

```bash
$ ogon gen resource User
[OGON-G0001] unowned file
  what:    refusing to overwrite user-owned file: models/User.go
  severity: error
  remedy:  re-run with --force, or move/delete the file
✓ gen resource User
  create models/User.go  (unowned file!)
  ...
```

Without `--force`, the exit code is 5 (`ExitGenConflict`).

### OGON-G0001 with --force (downgraded to warning)

```bash
$ ogon gen resource User --force
[OGON-G0001] unowned file
  what:    overwriting user-owned file: models/User.go
  severity: warning
  remedy:  (downgraded because --force was passed)
✓ gen resource User
  update models/User.go
  ...
```

---

## Remedy

1. **Re-run with `--force`** if you accept that the file will be
   overwritten with the generated version.
2. **Move / delete the file** if the file should remain user-owned.
3. **Add the ownership marker** (`// Code generated by ogon. DO NOT EDIT.`)
   to the top of the file if it should be both hand-edited and
   regenerable — this is unusual; prefer one or the other.

---

## Escape

- **`--force`**: downgrades the conflict from error to warning; the
  file is overwritten. Use only when you understand the diff.
- **`--dry-run`**: shows the conflict as a warning without writing
  anything. The exit code is still 0 if the only failures are
  conflicts.
- **Skip generation**: write the file by hand. The CLI never touches
  unowned files unless `--force` is passed.
- **Custom template**: `ogon gen route orders --template
  ./templates/custom_route.tmpl`. The custom template must exist
  (else `OGON-G0003`).

---

## Troubleshoot

| Symptom                                              | Fix                                                            |
|------------------------------------------------------|----------------------------------------------------------------|
| `OGON-G0001` after merging a PR                       | The merge brought a hand-written file that the CLI wants to regenerate; pass `--force` once. |
| `OGON-G0002` plan invalid                              | The generator has nothing to do; check the kind/name pair.    |
| `OGON-G0003` template not found                       | The custom template path is wrong; check the flag value.      |
| Generated file keeps getting overwritten               | The file's ownership marker is missing; add `// Code generated by ogon. DO NOT EDIT.` at the top. |
